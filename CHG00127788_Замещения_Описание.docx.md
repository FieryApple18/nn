## 1. Общие сведения

### 1.1. Идентификатор задачи
**CHG00127788** — задача по реализации функциональности «Замещения» в системе Directum RX.

### 1.2. Область применения
Функциональность предназначена для автоматизации процесса создания и управления замещениями сотрудников в период их временного отсутствия (например, во время отпуска) через интеграцию с Личным кабинетом сотрудника и внешней системой КЭДО.

### 1.3. Компоненты решения
Реализация включает следующие компоненты:
- **DirRX.NNOtherProcesses** — основной модуль, содержащий справочники и логику работы с замещениями
- **EssConfig/Vacations** — конфигурация ESS (Employee Self Service), включающая интерфейсные формы и скрипты валидации
- **DirRX.OverrideSolution** — расширения типовых объектов для поддержки замещений

## 2. Назначение функциональности

### 2.1. Цель внедрения
Функциональность «Замещения» решает задачу автоматического создания записей о замещении сотрудников в период их отсутствия. Это обеспечивает:
- Непрерывность бизнес-процессов во время отсутствия ключевых сотрудников
- Автоматическую синхронизацию данных о замещениях между Directum RX и смежными системами (КЭДО)
- Возможность для сотрудников самостоятельно указывать замещающих коллег через Личный кабинет

### 2.2. Основные возможности
1. **Создание записей о замещении** — фиксация информации о замещаемом сотруднике, замещающем лице, периоде замещения и системе, в которой требуется замещение
2. **Валидация периодов замещения** — проверка корректности дат замещения относительно периода отсутствия сотрудника
3. **Статусная модель** — отслеживание статуса отправки данных о замещении во внешние системы
4. **Автоматическая очистка** — удаление устаревших записей по истечении настроенного срока хранения
5. **Интеграция с КЭДО** — передача данных о замещениях в систему КЭДО для обеспечения юридически значимого документооборота

## 3. Объектная модель

### 3.1. Справочник «Системы для замещения» (SubstitutionSystem)

#### Назначение
Справочник содержит информацию о внешних системах, в которых может быть оформлено замещение. По умолчанию используется система КЭДО.

#### Структура сущности

| Свойство | Тип | Обязательное | Описание |
|----------|-----|--------------|----------|
| Name | String | Да | Полное наименование системы |
| ShortName | String | Да | Краткое наименование системы |
| SystemId | String | Да | Уникальный идентификатор системы во внешней среде |
| Functions | Text | Да | Перечень функций системы, доступных для замещения |
| Status | Enumeration | Да | Статус записи справочника |

#### Ключевые характеристики
- **Code:** `SubstitutionSy`
- **IntegrationServiceName:** `NNOtherProcessesSubstitutionSystem`
- **Поддержка поиска:** включена
- **Поддержка интеграции:** включена
- **Публичная функция:** `GetDefaultRecord()` — получение записи системы по умолчанию (КЭДО)

#### Запись по умолчанию
Запись по умолчанию определяется по идентификатору системы КЭДО (`IS0000098`). Значение может быть переопределено через константу `SubstitutionSystemKedoSystemId`.

---

### 3.2. Справочник «Замещения ЛК» (SubstitutionPersonalAccount)

#### Назначение
Справочник хранит информацию о конкретных замещениях, созданных через Личный кабинет сотрудника. Каждая запись соответствует одному факту замещения на определённый период.

#### Структура сущности

| Свойство | Тип | Обязательное | Описание |
|----------|-----|--------------|----------|
| Name | String | Да | Автоматически формируемое наименование записи |
| Created | DateTime | Нет | Дата и время создания замещения |
| SubstitutionSystem | Navigation | Да | Ссылка на запись справочника «Системы для замещения» |
| Employee | Navigation | Да | Замещаемый сотрудник (тип: Employee) |
| Substitute | Navigation | Да | Замещающий сотрудник (тип: Employee) |
| StartDate | DateTime | Да | Дата начала периода замещения |
| EndDate | DateTime | Нет | Дата окончания периода замещения |
| SentDate | DateTime | Нет | Дата и время отправки данных во внешнюю систему |
| SentStatus | Enumeration | Да | Статус отправки данных во внешнюю систему |
| ErrorText | Text | Нет | Текст ошибки при отправке во внешнюю систему |
| SourceTask | String | Нет | Идентификатор задачи-источника создания записи |

#### Статусы отправки (SentStatus)

| Код статуса | Наименование | Описание |
|-------------|--------------|----------|
| Created | Создано | Запись создана, но ещё не отправлена |
| Sent | Отправлено | Данные успешно отправлены во внешнюю систему |
| Assigned | Назначено | Замещение подтверждено и активировано во внешней системе |
| Error | Ошибка | При отправке или обработке возникла ошибка |
| Cancelled | Отменено | Замещение отменено |

#### Ключевые характеристики
- **Code:** `SubstitutionPe`
- **IntegrationServiceName:** `NNOtherProcessesSubstitutionPersonalAccount`
- **Авто-создание:** включено (IsAutoCreated = true)
- **Поддержка поиска:** включена
- **Поддержка интеграции:** включена

#### Формат наименования записи
Наименование формируется автоматически по шаблону:
```
{Замещающий} {Замещаемый} с {Дата начала} по {Дата окончания} в {Система}
```

Пример: *Иванов А.А. Петров Б.Б. с 01.06.2025 по 14.06.2025 в КЭДО*

## 5. Интеграция с Личным кабинетом

### 5.1. Интерфейс пользователя (ESS)

#### Форма «Настройка замещения» (NNSubstitutionSetup)
Форма предоставляется сотруднику в Личном кабинете для указания информации о замещении на период отсутствия.

**Параметры формы:**

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| InitiatorId | String | Да | Идентификатор инициатора (сотрудника) |
| VacationStartDate | DateTime | Нет | Дата начала отпуска/отсутствия |
| VacationEndDate | DateTime | Нет | Дата окончания отпуска/отсутствия |
| VacationPeriodsJson | String | Нет | JSON-представление периодов отпуска |
| AssignmentId | String | Нет | Идентификатор задачи назначения |
| AssignmentType | String | Нет | Тип задачи назначения |
| SystemsInfoBlock | String | Нет | Информационный блок о системах |
| VacationPeriodsDisplay | String | Нет | Отображение периодов отпуска для пользователя |
| DefaultSystemId | String | Нет | Идентификатор системы по умолчанию |

**Параметры выбора значений:**
- `Substitute` — запрос для получения списка доступных сотрудников для замещения
- `System` — запрос для получения списка систем для замещения

**Таблица ввода данных:**
Пользователь заполняет таблицу со следующими колонками:
1. **Замещающий** — выбор сотрудника из списка
2. **Система** — выбор системы для замещения
3. **Дата начала** — начало периода замещения
4. **Дата окончания** — окончание периода замещения

#### Элементы формы
1. **Информационный блок о системах** — выводит справку о том, в каких системах будет оформлено замещение
2. **Блок периодов отпуска** — отображает периоды отсутствия сотрудника (для контроля)
3. **Инструкция** — текстовая инструкция по заполнению формы
4. **Таблица замещений** — основная таблица для ввода данных о замещениях

### 5.2. Скрипты валидации

#### validateSubstitutionDates.js
Клиентский скрипт для проверки корректности дат замещения.

**Входные параметры:**
- `VacationPeriodsJson` — JSON с периодами отпуска
- `StartDatesString` — строка с датами начала замещений (разделитель `;`)
- `EndDatesString` — строка с датами окончания замещений (разделитель `;`)
- `IsCallingService` — флаг вызова из сервиса (для формирования разных сообщений об ошибках)

**Проверки:**
1. **Пустые значения** — если даты не указаны, валидация проходит успешно
2. **Наличие периодов отпуска** — если периоды отпуска не определены, возвращается ошибка
3. **Соответствие количества дат** — количество дат начала должно совпадать с количеством дат окончания
4. **Корректность диапазона** — дата начала не должна быть позже даты окончания
5. **Попадание в период отпуска** — даты замещения должны находиться внутри периодов отпуска
6. **Пересечение периодов** — даты замещения не должны охватывать несколько периодов отпуска

**Возвращаемое значение:**
```javascript
{
  isValid: boolean,  // Результат валидации
  errors: [          // Список ошибок
    {
      rowIndex: number,  // Индекс строки с ошибкой
      field: string,     // Поле с ошибкой
      message: string    // Текст ошибки
    }
  ]
}
```

**Локализация сообщений об ошибках:**
- `FACILITIES_NN_SUBSTITUTION_SETUP_DATE_OUT_OF_PERIOD` — дата выходит за пределы периода
- `FACILITIES_NN_SUBSTITUTION_SETUP_START_AFTER_END` — дата начала позже даты окончания
- `FACILITIES_NN_SUBSTITUTION_SETUP_DATES_SPAN_PERIODS` — даты охватывают несколько периодов
- `FACILITIES_NN_SUBSTITUTION_SETUP_CHECK_ERROR` — общая ошибка проверки
- `FACILITIES_NN_SUBSTITUTION_SETUP_DATE_MISMATCH` — несоответствие дат (для серверной валидации)

## 6. Сценарии использования

### 6.1. Создание замещения через Личный кабинет

**Шаг 1.** Сотрудник инициирует процесс оформления отпуска через Личный кабинет.

**Шаг 2.** Система открывает форму «Настройка замещения» (NNSubstitutionSetup).

**Шаг 3.** Сотрудник заполняет таблицу замещений:
- Выбирает замещающего сотрудника
- Выбирает систему (по умолчанию КЭДО)
- Указывает период замещения (автоматически подставляется период отпуска)

**Шаг 4.** Система выполняет клиентскую валидацию дат через скрипт `validateSubstitutionDates.js`.

**Шаг 5.** После успешной валидации данные отправляются на сервер.

**Шаг 6.** Серверная функция `CreateRecord` создаёт запись в справочнике «Замещения ЛК»:
- Формируется наименование записи
- Устанавливается дата создания
- Заполняются ссылки на сотрудника и замещающего
- Устанавливаются даты периода
- Присваивается статус `Assigned`

**Шаг 7.** Запись сохраняется в базе данных.

---

### 6.2. Отмена замещения

**Шаг 1.** Инициируется процесс отмены замещения (например, при отмене отпуска).

**Шаг 2.** Вызывается функция `CancelRecords`, которая:
- Получает все активные записи по критериям (сотрудник, замещающий, период, система)
- Для каждой записи устанавливает статус `Cancelled`
- Сохраняет изменения

**Шаг 3.** Изменения фиксируются в базе данных.

---

### 6.3. Поиск записей по замещению

Функция `GetRecords` используется для поиска существующих записей о замещении по следующим критериям:
- Сотрудник (Employee.Id)
- Замещающий (Substitute.Id)
- Система замещения (SubstitutionSystem.Id)
- Период замещения (StartDate, EndDate)
- Статус отправки (SentStatus = Assigned)

## 7. Фоновые процессы

### 7.1. Очистка устаревших записей (CleanSubstitutionPersonalAccountJob)

#### Назначение
Автоматическое удаление записей из справочника «Замещения ЛК» по истечении настроенного срока хранения.

#### Параметры
- **Срок хранения:** настраивается через константу `SubstitutionPersonalAccountRetentionDays` (по умолчанию 365 дней)

#### Алгоритм работы
1. Получение значения константы срока хранения
2. Расчёт граничной даты: `Calendar.Today.AddDays(-retentionDays)`
3. Выборка всех записей, у которых `EndDate < borderDate`
4. Попытка удаления каждой записи в транзакции
5. Подсчёт успешно удалённых записей и ошибок
6. Логирование результатов

#### Логирование
- **Старт:** `CleanSubstitutionPersonalAccountJob. Start. RetentionDays = {value}, borderDate = {date}.`
- **Удаление:** `CleanSubstitutionPersonalAccountJob. Finished. Deleted {count}, errors {count}.`
- **Ошибки:** `CleanSubstitutionPersonalAccountJob. Error while deleting recordId={id}, {message}.`

---

### 7.2. Актуализация признака TOP-10/100 (UpdateTopAttributeInDocumentsJob)

#### Назначение
Фоновый процесс для синхронизации признака принадлежности сотрудника к категории TOP-10/100 в документах, связанных с работой.

#### Особенности
- Исключает документы типа «Заявка на привлечение к работе в ВД/ПД/СР» (признак устанавливается вручную)
- Обрабатывает документы пакетами (размер пакета настраивается через константу)
- Использует блокировку документов для предотвращения конфликтов
- Отправляет уведомление администраторам, если обнаружены документы, требующие актуализации

## 9. Валидация данных

### 9.1. Клиентская валидация
Выполняется в браузере пользователя перед отправкой данных на сервер.

**Преимущества:**
- Мгновенная обратная связь для пользователя
- Снижение нагрузки на сервер
- Предотвращение отправки заведомо некорректных данных

**Недостатки:**
- Может быть обойдена пользователем
- Требует дублирования логики на сервере

### 9.2. Серверная валидация
Выполняется на стороне сервера при сохранении данных.

**Проверки:**
- Корректность ссылок на сотрудников
- Корректность ссылок на систему замещения
- Непротиворечивость дат (StartDate <= EndDate)
- Уникальность записей (при необходимости)

### 9.3. Валидация периодов
Особое внимание уделяется проверке соответствия периодов замещения периодам отсутствия сотрудника:
- Даты замещения должны находиться внутри периодов отпуска
- Один период замещения не может охватывать несколько периодов отпуска
- При множественных периодах отпуска требуется создание отдельных записей замещения для каждого периода

## 10. Логирование и обработка ошибок

### 10.1. Уровни логирования

| Уровень | Метод | Назначение |
|---------|-------|------------|
| Debug | `Logger.DebugFormat` | Отладочная информация о ходе выполнения операций |
| Error | `Logger.ErrorFormat` | Информация об ошибках и исключениях |

### 10.2. Формат логов

**Создание записи:**
```
{prefix}. CreateRecord. Start.
{prefix}. CreateRecord. End. Created recordId={id}.
```

**Отмена записи:**
```
{prefix}. CancelRecords. Start.
{prefix}. CancelRecords. End. Not found records by criteria.
{prefix}. CancelRecords. Cancelled recordId={id}.
```

**Получение записей:**
```
{prefix}. GetRecords. Start.
{prefix}. GetRecords. End. Found {count} records by criteria.
{prefix}. GetRecords. End. Not found default record in SubstitutionSystem.
```

**Фоновый процесс очистки:**
```
CleanSubstitutionPersonalAccountJob. Start. RetentionDays = {days}, borderDate = {date}.
CleanSubstitutionPersonalAccountJob. Finished. Deleted {count}, errors {count}.
CleanSubstitutionPersonalAccountJob. Error while deleting recordId={id}, {message}.
```

### 10.3. Обработка ошибок

**При создании записи:**
- Проверка наличия системы по умолчанию
- Фиксация исключений с логированием
- Возврат null при ошибке

**При удалении записей:**
- Использование транзакций для атомарности операций
- Продолжение обработки при ошибке удаления отдельной записи
- Подсчёт ошибок для последующего анализа

**При валидации:**
- Возврат структурированного списка ошибок
- Разделение ошибок по полям и строкам таблицы
- Локализация сообщений об ошибках
