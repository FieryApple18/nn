# Описание функционала «Замещения в разных информационных системах»

## 1. Введение

Сервис «Замещения в разных информационных системах» предназначен для автоматизации процесса назначения замещающих сотрудников на период отсутствия основного работника (отпуск, командировка и т.д.) в различных внешних информационных системах (на текущий момент — КЭДО).

Функционал позволяет:
- Вести реестр систем, поддерживающих замещения.
- Фиксировать историю назначений замещений.
- Автоматически создавать, обновлять и отменять замещения при изменении периодов отпуска.
- Контролировать актуальность данных и очищать устаревшие записи.

## 2. Объектная модель

### 2.1. Справочник «Список систем для замещения» (SubstitutionSystem)

Предназначен для хранения реестра внешних систем, в которых возможно назначение замещений.

**Общая информация:**
- **Модуль:** `NNOtherProcesses`
- **Базовый тип:** `Sungero.CoreEntities.DatabookEntry`
- **GUID типа:** `55f01030-a8b4-45be-9734-c09ee9ee0862`
- **Способ создания:** Вручную администратором.
- **Права доступа:** Чтение — всем пользователям; Создание/Изменение/Удаление — только администраторам.

При инициализации модуля автоматически создается запись по умолчанию для системы КЭДО (`SystemId = IS0000098`).

**Таблица 1. Свойства справочника SubstitutionSystem**

| Наименование | Код | Тип данных | Обязательное | Уникальное | Описание |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ИД | `Id` | Идентификатор | Да | Да | Системный идентификатор записи. |
| Состояние | `Status` | Перечисление | Да | Нет | Статус записи в справочнике. |
| Наименование | `Name` | Строка (250) | Да | Нет | Полное название системы. |
| Краткое наименование | `ShortName` | Строка (250) | Да | Нет | Краткое наименование для отображения. |

| ИД системы | `SystemId` | Строка (250) | Да | Да | Внешний уникальный идентификатор системы. |

| Код | Наименование | Описание |
| :--- | :--- | :--- |
| `Active` | Действующая | Система активна, замещения могут создаваться. |

- **Метод `CreateRecord`:** Создает запись справочника с обязательной проверкой на дубликаты по полю `SystemId`.
- **Метод `GetDefaultRecord`:** Возвращает запись справочника по умолчанию (КЭДО).

### 2.2. Справочник «Замещения ЛК» (SubstitutionPersonalAccount)

Журнал истории создания и управления замещениями сотрудников во внешних системах. Записи создаются программно в ходе выполнения бизнес-процессов.

**Общая информация:**
- **Модуль:** `NNOtherProcesses`
- **Базовый тип:** `Sungero.CoreEntities.DatabookEntry`
- **GUID типа:** `3404F89F-BB72-47E6-8F82-CEB5C72349DC`
- **Способ создания:** Программно.
- **Права доступа:** Чтение — всем пользователям; Остальные операции — только программно.

| Код | Наименование | Описание |

| `Cancelled` | Отменено | Замещение отменено (например, при отзыве из отпуска). |

**Методы и события:**
- **Событие `Created`:** Автоматическая установка статуса `Created`.
- **Метод `CreateRecord`:** Перегруженный метод для создания записи на основе интерфейсов `ISubstitution` или `ISubstitutionInfo`. Выполняет проверку существующих записей.
- **Метод `GetRecords`:** Поиск записей справочника по关联ной задаче или замещению.
- **Метод `CancelRecords`:** Массовая отмена записей по условию с установкой статуса `Cancelled`.

## 3. Расширение типов задач

Для поддержки функционала замещений расширены следующие типы задач:
1.  **«Задача на рассмотрение заявлений сотрудников»** (`StatementTask`)
2.  **«Задача на подтверждение дат отпуска»** (`RegistrationOfAnnualLeave`)

В данные типы добавлена коллекция **`SubstitutionsDirRX`**, хранящая информацию о планируемых замещениях.

**Таблица 5. Свойства коллекции SubstitutionsDirRX**

| Наименование | Код | Тип данных | Описание |
| :--- | :--- | :--- | :--- |
| ИД | `Id` | Идентификатор | Системный ID строки. |
| Замещающий | `Substitute` | Ссылка (Сотрудник) | Сотрудник, который будет замещать. |
| Система | `SubstitutionSystem` | Ссылка | Система, в которой назначается замещение. |
| Дата начала | `StartDate` | Дата | Начало периода. |
| Дата окончания | `EndDate` | Дата | Окончание периода. |

### 3.1. Механизм передачи данных из услуг

Для интеграции с услугами (где невозможно передать сложные коллекции напрямую) в задачу `StatementTask` добавлены временные строковые свойства:
- `SubstituteIdsDirRX`
- `SystemIdsDirRX`
- `StartDatesDirRX`
- `EndDatesDirRX`

**Логика преобразования:**
В событии серверного обработчика **`BeforeSave`** задачи `StatementTask` вызывается метод `AddSubstitutions()`.
- **Условие выполнения:** Только при создании задачи (`IsInserted == true`).
- **Действие:** Строковые значения, разделенные точкой с запятой (`;`), разбираются и преобразуются в строки коллекции `SubstitutionsDirRX`. После преобразования строковые свойства очищаются.

## 4. Серверная бизнес-логика (Модуль NNVacations)

Вся основная логика работы с замещениями инкапсулирована в серверных методах модуля `NNVacations`.

### 4.1. Основные методы управления

#### Метод `CreateSubstitutionsFromTask`
**Назначение:** Создание записей в справочниках «Замещения» и «Замещения ЛК» после утверждения приказа об отпуске.
**Алгоритм работы:**
1.  Извлечение данных из задачи (ведущая задача, приказ, сотрудник).
2.  Получение коллекции `SubstitutionsDirRX` из задачи.
3.  Цикл по каждой строке коллекции:
    - Создание записи в справочнике `SubstitutionPersonalAccount`.
    - Если выбрана система КЭДО — создание соответствующей записи в справочнике `SubstitutionSystem` (при необходимости).
    - Установка даты создания и статуса `Assigned` («Замещение назначено») для созданной записи.

#### Метод `UpdateSubstitutionsFromTask`
**Назначение:** Актуализация периодов замещения при отзыве сотрудника из отпуска или изменении дат.
**Алгоритм работы:**
1.  Извлечение данных о новом периоде отзыва/прерывания.
2.  Поиск существующих активных записей замещений по сотруднику и исходному периоду.
3.  Анализ пересечения периодов для каждой найденной записи:
    - **Нет пересечения:** Запись не изменяется.
    - **Полное совпадение:** Период отзыва полностью перекрывает период замещения. Запись закрывается (статус `Close`), связанные записи в `SubstitutionPersonalAccount` получают статус `Cancelled`.
    - **Пересечение в середине:** Период отзыва разрывает период замещения.
        - Текущая запись усекается до даты начала отзыва.
        - Создается новая запись на период после даты окончания отзыва.
        - Создаются новые записи в `SubstitutionPersonalAccount` для обоих периодов.
    - **Пересечение в начале:** Отзыв начинается в начале замещения.
        - Дата начала замещения сдвигается на дату после окончания отзыва.
        - Если новая дата начала > даты окончания, запись закрывается.
    - **Пересечение в конце:** Отзыв происходит в конце периода замещения.
        - Дата окончания замещения сдвигается на дату перед началом отзыва.
        - Если новая дата окончания < даты начала, запись закрывается.
4.  Для всех затронутых записей в `SubstitutionPersonalAccount` старые активные записи отменяются (`Cancelled`), создаются новые.

#### Метод `CloseSubstitutionsFromTask`
**Назначение:** Полная отмена замещений при переносе или отмене отпуска.
**Алгоритм работы:**
1.  Поиск всех активных записей замещений по сотруднику и периоду.
2.  Для каждой записи:
    - Поиск связанных записей в `SubstitutionPersonalAccount` со статусом `Assigned`.
    - Установка им статуса `Cancelled`.
    - Установка состоянию записи замещения значения `Close` («Закрытая»).

### 4.2. Вспомогательные методы

- `TryExtractDataForSubstitutionFromTask`: Валидация входных данных задачи и сбор информации в структуру.
- `GetVacationOrderDocumentFromTask` / `GetVacationStatementDocumentFromTask`: Извлечение вложений (приказ, заявление) из задачи.
- `GetOriginalPeriodFromStatement` / `GetRecallPeriodFromStatement`: Парсинг периодов из текста заявления.
- `FindExistingSubstitutions`: Поиск записей в БД по критериям (сотрудник, даты, система).
- `GetSubstitutionTextForEmployee`: Формирование человеко-читаемого списка замещений для инструкций (например: *«Иванов И.И. в КЭДО с 01.06.2024 по 14.06.2024»*).

### 4.3. Интеграционные API методы (GET/POST)

Методы для взаимодействия с клиентской частью услуг:
- `GetSubstitutionSystems`: Возврат списка активных систем (JSON).
- `GetEmployeesForSubstitution`: Возврат списка доступных сотрудников для выбора (с учетом ограничений).
- `ValidateSubstitute`: Проверка выбранного сотрудника на коллизии (отпуска, командировки) во внешних системах.
- `SaveSubstitutionsToTask`: Сохранение данных из формы услуги в строковые параметры задачи.

## 5. Блоки «Скрипт» в бизнес-процессах

В схемах бизнес-процессов используются блоки типа «Скрипт», которые вызывают описанные выше серверные методы модуля `NNVacations`.

### 5.1. Скрипт «Создать замещения»
**Момент вызова:** После утверждения приказа об отпуске.
**Используемый метод:** `CreateSubstitutionsFromTask`.
**Логика:**
1.  Валидация входных параметров (задача, приказ).
2.  Вызов метода создания.
3.  Логирование результата.

### 5.2. Скрипт «Обновить замещения»
**Момент вызова:** При обработке заявления на отзыв из отпуска.
**Используемый метод:** `UpdateSubstitutionsFromTask`.
**Логика:**
1.  Определение исходного и нового периодов.
2.  Вызов метода обновления, который выполняет сложную логику разрезания периодов (см. п. 4.1).
3.  Обновление статусов в журнале `SubstitutionPersonalAccount`.

### 5.3. Скрипт «Закрыть замещения»
**Момент вызова:** При отмене отпуска или переносе дат.
**Используемый метод:** `CloseSubstitutionsFromTask`.
**Логика:**
1.  Вызов метода закрытия.
2.  Массовая отмена активных записей в журнале.
3.  Архивирование записей справочника.

## 6. Фоновые процессы

### Процесс «Очистка записей справочника Замещения ЛК» (CleanSubstitutionPersonalAccountJob)
**Назначение:** Автоматическое удаление устаревших записей из справочника `SubstitutionPersonalAccount` для поддержания производительности.

**Алгоритм работы:**
1.  Чтение константы «Количество дней хранения» (по умолчанию 365 дней).
2.  Расчет граничной даты: `ГраничнаяДата = ТекущаяДата - ДниХранения`.
3.  Выборка записей, где `EndDate < ГраничнаяДата`.
4.  Удаление записей в транзакции.
5.  Запись в лог количества удаленных записей.

## 7. Пользовательский интерфейс и Услуги

### 7.1. Услуга «Настройка замещений» (NNSubstitutionSetup)
Единый интерфейс для выбора замещающих. Позволяет назначать нескольких сотрудников на разные периоды.

**Особенности:**
- **Сохранение состояния:** Использует `localStorage` браузера для сохранения введенных данных при переходе между шагами или случайном закрытии вкладки.
- **Мультипериодность:** Поддержка работы с несколькими периодами отпуска одновременно (актуально для переносов).
- **Параметры:** Принимает JSON с периодами, ID инициатора, и возвращает строковые списки ID сотрудников, систем и дат.

### 7.2. Клиентская валидация (validateSubstitutionDates.js)
Скрипт выполняет предварительную проверку корректности дат на стороне клиента перед отправкой формы.

**Проверяемые условия:**
1.  Дата окончания не раньше даты начала.
2.  Даты замещения находятся строго внутри периода отпуска.
3.  Даты замещения не пересекают границы разных периодов отпуска (если их несколько).

### 7.3. Доработка услуг оформления отпусков
Во все услуги оформления, переноса и доработки отпусков внедрены элементы управления замещениями:
- Кнопка **«Определить замещающих»**: Открывает услугу `NNSubstitutionSetup`.
- Кнопка **«Показать замещающих»**: Выводит сводку выбранных сотрудников.
- Скрытые параметры для передачи данных в задачу.

**Список доработанных услуг:**
- Оформление ежегодного/прочего отпуска.
- Досрочное прерывание отпуска.
- Перенос отпуска (из заявления и из задания).
- Все виды доработок (Rework) вышеуказанных процессов.

## 8. Константы модуля

В модуле `NNOtherProcesses` создана группа констант «Замещения»:
1.  **Количество дней хранения записей:** Целое число (default: 365). Регулирует работу фонового процесса очистки.
2.  **ИД системы КЭДО по умолчанию:** Строка (default: `IS0000098`). Используется для автоматического подставления системы при создании записей.
